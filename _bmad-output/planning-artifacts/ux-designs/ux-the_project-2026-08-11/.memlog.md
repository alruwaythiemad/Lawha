- (decision) Light AND dark from day one, both directions (4 combinations total: light-LTR, light-RTL, dark-LTR, dark-RTL). D suits this — having no shadows or tints, it inverts cleanly rather than needing a re-tuned palette.
- (event) FINDING (favours D): direction D requires no modern CSS. No shadows, tints, or gradients means it renders identically on the player's Chromium 76 baseline and on current Chrome. The other three directions would have needed a degraded player variant.
- (event) BLOCKER FOUND — Arabic has no uppercase. D's identity leans on uppercase micro-labels at .16em tracking (STORAGE, MAIN BRANCH, OFFLINE, SCREENS). text-transform:uppercase is a no-op on Arabic, so the entire micro-label tier loses its differentiation in Arabic. Separately, letter-spacing breaks Arabic cursive joins and must be zeroed for Arabic — tracking cannot be the substitute. Needs an explicit non-case device for the Arabic label tier.
- (event) CONFLICT FOUND — FR-47 vs Chromium 76. FR-47 defines done mechanically as 'no physical left/right layout property'. But inset-inline-start / inset-inline-end shipped in Chrome 87, so they do not exist on the player's Chromium 76 baseline. Any absolutely-positioned mirrored element in the player — notably the FR-81 trial badge, which must mirror its corner with content direction — cannot use logical insets. Recommended resolution: mirror by flow and alignment (grid/flex with justify-items:end, direction-aware since Chrome 57) rather than by insets, which keeps FR-47 intact with no physical properties anywhere. Fallback if that fails: scope FR-47's mechanical rule to the console and grant the player a documented dir-scoped exemption. Flag to architecture either way.
- (event) GAP FOUND — the PRD does not specify how the player transitions between playlist items. FR-11 covers when changes take effect but not whether item-to-item is a hard cut or a fade. On a wall this is the most-seen visual behaviour in the product and D implies zero motion. Needs a decision.
- (decision) Arabic label tier resolution: uppercase is abandoned as the MECHANISM. The micro-label tier is defined by weight 800 at 10-11px in muted colour, identically in both languages. English may apply uppercase as a decorative flourish that carries no semantic load, so nothing is lost where it cannot apply. letter-spacing is 0 for Arabic in every tier — it breaks cursive joins.
- (decision) Arabic type family: Cairo, variable 200-1000. Chosen because D's identity is weight contrast (800 vs 500) and Cairo has the widest Arabic weight range available. Self-hosted, subset, precached in the app shell per AD-23 — never resolved from host fonts.
- (decision) Player item transition: short cross-fade, approx 200ms. This is the ONE motion exception in the product; the console stays at zero motion per direction D. Constraints to carry into the spines: crossfade is an opacity transition between two ALREADY-DECODED elements, which stays inside FR-10's one-item-ahead allowance; it must degrade to a hard cut on video-to-video and under memory pressure, because NFR-6 (no OOM kill during sustained decode) outranks the transition. CSS opacity transitions are compositor-driven and safe on Chromium 76.
- (decision) Multi-branch journey will be DERIVED strictly from FR-70 to FR-78 and tagged [ASSUMPTION] throughout. No invented protagonist, no invented motivation. Yusuf remains the only validated journey.
- (event) GAP FOUND — nothing notifies the owner of an offline screen outside the dashboard. NFR-7 guarantees an unreachable screen appears offline IN THE DASHBOARD within five minutes, and FR-63a specifies email only for payment failure. Under 'calm until it matters', a healthy dashboard shows almost nothing, which actively trains the owner not to check it. The product promise is 'the screen is never wrong and they never call anyone' — but an owner who never opens the dashboard learns nothing, so silent death remains effectively silent. This is a product-level gap the UX cannot close alone.
