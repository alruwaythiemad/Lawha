- (direction) Flash safety: user delegated the choice ('do the best option').
- (decision) Flash safety resolved as a layered answer, chosen because a single measure cannot carry a physical-harm item. (1) Client-side luminance-flash analysis in the uploader, before transfer begins — the uploader already enforces ceilings client-side, so this extends an existing pattern rather than adding a stage, and it needs no ingest pipeline, which the architecture spine rules out for v1. (2) A confident detection above the WCAG 2.3.1 general flash threshold is a hard block with rejection copy in the existing condition-plus-next-action shape. (3) Anything flagged uncertain, or that cannot be analysed at all, is a warning-and-acknowledgement rather than a silent pass. (4) A stated content policy backs all three. Residual risk recorded, not hidden: browser-side frame sampling is heuristic, so this reduces exposure rather than conforming, and full 2.3.1 conformance would need server-side analysis on ingest, which is out of this spec's scope.

- (decision) Storage allowance set to 10 GB per screen, pooled across the workspace (a 5-screen plan gets a 50 GB pool usable by any screen), matching the PRD's own 'storage allowance scales with the screen count' shape. Derivation: object storage (R2) runs roughly $0.015/GB-month, so 10 GB/screen costs about 15 cents against $5 of revenue — trivial, so generosity costs nothing. A working media set — several videos near the 150 MB ceiling plus a couple dozen images — lands around 1-2 GB, so 10 GB is 5-10x headroom before an owner has to think about deleting anything. Pooling rather than siloing per screen matches how owners actually reuse media: the same menu image assigned to several screens should not be charged once per screen. Closes PRD 12.2's storage row and the architecture spine's matching Deferred item.
